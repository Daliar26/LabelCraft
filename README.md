# LabelCraft

**Офлайн-редактор этикеток и печать на Bluetooth-термопринтерах.** Clean-room проект; код и ресурсы Tiny Print не используются.

Документация на английском: [README_EN.md](README_EN.md).

## Состояние проекта

Исходная реализация и CI-конфигурация подготовлены. APK в этой рабочей среде не собран: здесь нет Android SDK/Gradle, а сетевые DNS-запросы к Google и GitHub недоступны. Физические принтеры не подключены, поэтому совместимость реальных моделей пока не подтверждена. См. [DECISIONS.md](DECISIONS.md).

## Быстрый старт

Требуется JDK 17+, Android SDK Platform 36 и Build Tools 36.0.0.

```bash
# один раз, когда Gradle 8.13 доступен в PATH:
gradle wrapper --gradle-version 8.13 --distribution-type bin

# после генерации стандартного gradle-wrapper.jar:
./gradlew assembleDebug test
```

Debug APK после успешной сборки: `app/build/outputs/apk/debug/app-debug.apk`.

CI использует Gradle 8.13 через `gradle/actions/setup-gradle` и потому может выполнять сборку на GitHub-hosted runner независимо от отсутствующего локального wrapper JAR.

## Возможности реализации

- Bluetooth Classic SPP (RFCOMM SPP UUID) и BLE GATT write characteristic; обнаружение bonded/classic/BLE-устройств и повторные попытки подключения.
- Протокольные кодеры TSPL2, ESC/POS, CPCL и ZPL; автоопределение только по полученной signature/capability-строке. Если устройство не отвечает идентифицирующей строкой, протокол выбирается вручную.
- WYSIWYG-предпросмотр; текст, Code128, EAN-13, QR, изображение из галереи/камеры, линия/рамка, поворот текстового блока. Пресеты 40×30, 58×40, 100×150 мм и произвольный размер. JSON-шаблоны, импорт/экспорт, CSV-подстановка `{{column}}`.
- Размеры 20–110 мм × 10–300 мм, DPI 203/300, преобразование мм в точки, Bitmap ARGB_8888, Floyd–Steinberg 1-bit raster.
- Очередь задач с копиями, статусами, повтором неудачной задачи и локальным сохранением.
- Аппаратная прокрутка: volume keys, D-pad, Page Up/Down, настраиваемая карта keyCode/action, шаг мм, скорость, ускорение, инверсия; настройки отдельно для Bluetooth-устройства.
- Калибровка: команды TSPL gap/black-mark и ZPL `~JC`; ручной профиль с локальным сохранением.

## Bluetooth и сопряжение

1. Разрешите Bluetooth Scan/Connect (Android 12+) или Location для обнаружения на старых версиях Android.
2. Выполните поиск устройств. Для некоторых SPP-принтеров требуется предварительное системное сопряжение.
3. Подключите найденное устройство и выберите фактический язык принтера в меню «Протокол».
4. Отправьте тестовую этикетку на одном экземпляре, затем проверьте геометрию и плотность печати.

BLE использует первую доступную GATT characteristic с write/write-no-response. Некоторые производители используют нестандартные service UUID, framing, MTU, authentication или proprietary packet format; для таких моделей нужен профиль адаптера.

## Протоколы

- **TSPL2:** `SIZE`, `GAP`/`BLINE`, `CLS`, `BITMAP`, `PRINT`; calibration command `GAPDETECT` или `BLINEDETECT`.
- **ESC/POS:** `GS v 0` raster image.
- **CPCL:** генерация базового `EG` raster job; поля и упаковку бинарных данных надо сверять с руководством конкретной модели.
- **ZPL:** `^GFA` raster image и `~JC` calibration request.

Производители часто меняют реализацию команд между сериями и прошивками. Перед тиражом необходима пробная печать и проверка языка команд.

## Калибровка этикеток

Автоматический физический замер возможен только если прошивка принтера отдаёт приложению независимые значения энкодера/датчика. Сейчас адаптер распознаёт телеметрию формата:

```text
LABEL_PULSES=400;GAP_PULSES=24;PULSES_PER_MM=8
```

Для расчёта принимаются три и более измерения; используется медиана. Тестовый набор калибровочного калькулятора проверяет отклонение не более ±1 мм. Само выполнение `GAPDETECT`/`~JC` не доказывает, что принтер вернул физические измерения. Для прошивок без телеметрии используйте экран «Калибровка» и сохраните длину/ширину/зазор вручную. BLE status notifications и проприетарные команды разных производителей пока требуют отдельных адаптеров.

## Аппаратная прокрутка

По умолчанию работают `KEYCODE_VOLUME_UP/DOWN`, `DPAD_UP/DOWN`, `PAGE_UP/DOWN`. Формат пользовательской карты, например:

```text
24:SCROLL_UP,25:SCROLL_DOWN,92:PAGE_UP,93:PAGE_DOWN
```

Доступны шаг 0.5–30 мм, скорость 0.25–5×, ускорение 0.5–4× и инверсия. Профиль хранится локально по Bluetooth-адресу принтера. BLE HID-колесо, передающее Android событие pointer-scroll вместо key event, обрабатывается отдельным путём и использует тот же шаг/скорость/ускорение/инверсию; фактическую генерацию события нужно проверить на подключённом устройстве.

## Пакетная печать CSV

CSV должен содержать заголовки. В текстовых элементах шаблона укажите токены вида `{{name}}` и `{{sku}}`. Каждая строка данных создаёт отдельное задание в очереди. Поддерживаются запятые, кавычки, экранированные двойные кавычки и CRLF.

## CI и подписанный Release

- `.github/workflows/android-ci.yml` собирает debug и release APK и запускает агрегирующую задачу `test` для `testDebugUnitTest` каждого Android-модуля.
- `.github/workflows/release.yml` реагирует на тег `v*`, собирает подписанный APK и создаёт GitHub Release.
- В GitHub Actions → Settings → Secrets and variables → Actions создайте secrets: `RELEASE_KEYSTORE_BASE64`, `RELEASE_STORE_PASSWORD`, `RELEASE_KEY_ALIAS`, `RELEASE_KEY_PASSWORD`. Base64 — содержимое keystore. Keystore и пароли не должны попадать в git.

Ручная публикация после установки Gradle 8.13/JDK 17/Android SDK 36: `gh auth login`, добавьте четыре GitHub Secrets выше, затем выполните `gh repo create <owner>/labelcraft --source . --remote origin --push --private && git tag v0.1.0 && git push origin v0.1.0` (вместо `<owner>` укажите свой GitHub-аккаунт; имя репозитория должно быть свободно).

## Приватность и лицензии

Приложение работает локально: нет рекламы, аналитики, телеметрии, аккаунтов или обязательного облака. Разрешения используются для Bluetooth и выбора/съёмки изображения. Используемая ZXing Core поставляется под Apache-2.0; AndroidX — Apache-2.0. Проект — Apache-2.0, допускает коммерческое и закрытое распространение производных приложений.

## Тесты

45 unit-тестов покрывают конвертацию 203/300 DPI, медианный калибровочный расчёт, CSV, JSON, hardware key mapper, сенсорный парсер и протокольные byte-последовательности. Они добавлены в исходники; выполнение тестов в данной среде пока не подтверждено из-за отсутствующих Android SDK/Gradle.
